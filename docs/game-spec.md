# Jumping Jim — game specification (platform independent)

This document describes **what the game does**, reconstructed by reverse engineering the
original Z80 code (`original/JumpingJim_v4.nex`). It is the reference for every port.
`$xxxx` addresses point to the routine/table in the original binary. All numeric data
lives in `assets/jumpingjim.json` (generated by `tools/extract.py`).

## 1. Units and conventions

- Logical screen: **256×192 pixels** (32×24 cells of 8×8), like the ZX Spectrum.
- Coordinates: `x` 0–255 (a byte; it **wraps** from 255 to 0 for the player), `y` 0–191.
  An object's `y` is the line **its feet stand on** (the 16×16 sprite is drawn with its
  top edge at `y-16`).
- Time: everything advances **once per frame at 50 Hz**. Timers count frames.
- Unsigned 8-bit arithmetic with wrap-around, unless "signed" is stated.
- Colours: Spectrum attributes `FLASH<<7 | BRIGHT<<6 | PAPER<<3 | INK`. Each port maps
  them to its own palette (see `platforms/c64/tools/convert_c64.py` for an example).

## 2. Level structure

- 7 floors, index 0 (ground) to 6 (goal). `tables.floor_y = [184,160,136,112,88,64,40]`
  (character row = y/8: 23,20,17,14,11,8,5).
- Each floor is a strip **3 pixel lines thick** (lines 0–2 of its character row; lines
  3–7 are empty). Floor 0 is solid (8 lines, no gap).
- Floors 1–6 have **one gap** each: `gap_start[c]` (0–255) and `gap_len[c]` pixels.
  The gap moves `gap_speed[c]` pixels per update (signed, ±1/±2) and wraps around.
  Pixel `x` is inside the gap if `(x - gap_start) mod 256 < gap_len`.
- **Gap test** (`$84DC`): an object at `x` with width `w` falls through if
  `(x + off - gap_start) mod 256 < (gap_len - w) mod 256`.
  Values used: player falling `off=4,w=7`; head when jumping `off=2,w=11`;
  enemies `off=4,w=7`.

### Level setup (`$8BA7`)
1. `pal = (level-1) & 7` → `levels.palettes[pal]`: border, 8 background colour bands
   (3 rows each), the colour of each floor, and a name ("NIGHT SKY"…) centred on row 2
   (column `name_col`).
2. `base = 0x2C - 2*min(level-1, 8)`.
3. Speeds: `set = gap_speed_set_for_level[min(level-1,15)]`,
   `gap_speed[1..6] = gap_speed_sets[set]`.
4. For c=1..6: `gap_start[c] = random()`, `gap_len[c] = gap_len_add[(level+c) mod 6] + base`.
5. Spawn enemies, place the player, draw the HUD, "GET READY!" (row 1, column 11), music
   `level_music[(level-1) mod 12]`, wait **130 frames**, clear rows 1–2.

### Gap movement (`$85CC`)
Every frame (if `level < 3`, only on even frames of the global counter) for c=1..6:
`gap_start[c] += gap_speed[c]`.

## 3. Player (`$86A9`)

Variables: `x, y, vy (signed), state, floor, fall_count, timer, dir (0=right,1=left),
anim, invuln, jump_frame, moving`.

Respawn (`$8640`): `x=120, y=184, floor=0, state=0, invuln=90`.

Every frame: if `invuln>0`, `invuln--`. Then, depending on `state`:

| state | meaning | behaviour |
|---|---|---|
| 0 | standing/walking | *carry*: if floor≠0, `x += gap_speed[floor]` (the original does this on every frame even though on levels 1–2 the floors only move every other frame; recommended: only when the floors advance). Left/right: `x ∓= 3`, `moving=1`, `anim++`. If floor≠0 and over the gap (off 4, w 7) → **falls**: state=1, vy=1, fall_count=1, rainbow border for 30 frames, sfx *fall*. If not falling and jump is pressed → state=1, vy=−5, fall_count=0, sfx *jump*. |
| 1 | airborne | left/right `x ∓= 3`. `ny = y + vy`. If vy<0: **head** — for c=1..6 with `d = floor_y[c]+19`, if `y ≥ d > ny` and NOT under the gap (off 2, w 11) → `ny = d, vy = 0`. If vy≥0: **landing** — for c=0..6 with `d=floor_y[c]`, if `y < d ≤ ny`: if c≠0 and over the gap → passes through (`fall_count++`; the first time also rainbow + sfx *fall*); otherwise → **lands**. While still airborne: `y=ny`; on odd values of `jump_frame`, `vy++` (max 6). |
| 2 | stunned | carry + fall test; `timer--`, at 0 → state 0. |
| 3 | dying | if `y<200`: `y += vy`, `vy++` (max 7). `timer--`; at 0: `lives--`; no lives left → game over; otherwise respawn. |
| 4 | level complete | `timer--`; at 0 → next level. *(Original: no carry. Recommended for ports: apply the carry here too.)* |

**Landing on floor c** (`$8825`): `y=floor_y[c]`, state 0, vy 0. If `c >` previous floor:
+10 points, sfx *climb*. If c=6: state 4, timer 150, +`level`×100 points (BCD), text
"LEVEL COMPLETE!" (row 1, column 8), music 3. Otherwise, if `fall_count>0`: stunned,
`timer = 40 + 12*fall_count` (8 bits), sfx *stunned*.

Sprite frame (`$8417`): airborne→5, stunned→6+((timer>>3)&1), dying→8,
level complete→9, walking→(anim>>2)&3, idle→4. Mirrored if dir=1. Invisible when
`invuln & 4` (blinking).

## 4. Enemies (`$88DA`, `$8975`)

Up to 8. Record: `state (0 free, 1 walking, 2 falling), floor, x, y, speed (signed),
kind|variant<<3, anim, yoff`.

**Spawning**: `n = min(level+1, 8)`. Enemy i (0..n−1): floor = `i mod 5 + 1`,
`y = floor_y[floor]`, `x = random() mod 240`, `kind = i`, `speed = enemy_speed[i]`,
`variant = (level+i) mod 3`, random direction.

**Every frame** (state 1; if `level<3`, only on even frames, but `anim++` always):
- kind 3: `yoff = bob[anim&31]`; kind 4: `yoff = 2*bob[anim&31]`;
- kind 6: `yoff = 10 + 2*((anim>>3)&1)`;
- kinds 2 and 7 **chase**: if on the player's floor and the player is not dying,
  `speed = ±enemy_speed[kind]` towards him;
- kind 5 (robot): when `anim & 0x40` it does not move that frame (walks 64 frames, stops 64). *Recommended for ports: while stopped, carry it with the floor like Jim.*
- movement: `x += speed`, bounces at 0 and 240 (speed is negated).
- If its floor ≠ 0 and it is over the gap → state 2 and `floor--`; if it reaches 0 it
  reappears at the top: `y = 8, floor = 5`.
- State 2: `y += 3` until `floor_y[floor]` → state 1.

Frame: `variant*16 + kind*2 + ((anim>>3)&1)`, mirrored if speed<0. It is drawn with the
16×16 box at `(x, y - yoff - 16)` (the 12×11 artwork covers x+2..x+13, y+5..y+15).

**Collision** (`$8AA7`): if invuln=0 and state<3, for each enemy in state 1:
`|y_p - (y_e - yoff)| < 8` and `|x_p - x_e| < 9` → state 3, timer 70, vy −6, sfx *death*.

## 5. Game flow

```
title → new game (3 lives, level 1, score 0)
  └─ loop: set up level → play
        level complete → level++, (every 4 levels +1 life, max 5)
        no lives left → GAME OVER screen → title
```
Game loop (`$8CEA`): wait for frame → read controls → move gaps → player →
enemies → collisions → sprites → HUD if it changed.

**HUD** (row 0): `SCORE 000000   LEVEL 01  ♥♥♥    ` — colours: columns 0–11 yellow,
12–24 cyan, 25–31 red (the hearts are the `#` character of the font).

**Controls**: right P/X, left O/Z, jump Q/SPACE, start SPACE/ENTER/fire;
joystick: up or fire = jump (fire also starts).

## 6. Screens

- **Title** (`$8D1C`): 256×48 "JUMPING JIM" logo (rows 1–6) drawn from the 37
  segments in `title_logo` (2 px stroke). Animated with `t = 0..239` (cyclic):
  `lv = title_logo_level[t]`; if lv<7 each segment is offset by `(dx>>lv, dy>>lv)`
  (they fly in); if lv=7 they wiggle by 1 px: `dx = ((t>>2) + index) & 1`. Rainbow
  colours per column scroll every 4 frames (rows 1–7). At `t=42` the digitised voice
  plays, followed by music 2. Jim and an enemy walk along the ground.
- **Game Over** (`$8EF7`): "GAME OVER" (16 px, red), a 144×144 crying face at (column 7,
  row 2), two animated tears (sprite *drop*), final score and high score; music 4;
  after 150 frames "PRESS SPACE OR FIRE" flashes.
- **Rainbow border**: while `flash > 0` (30 frames after falling into a gap), scrolling
  stripes of `border_rainbow` colours.

## 7. Sound

- Original chip: AY-3-8912 at 1.75 MHz. Frequency = 1 750 000 / (16 × period).
- **Music** (`$80EA`): 15 tunes; 4-byte rows `A, B, C, drum`. Note 0 = silence,
  0xFF = hold, n = `note_periods[n]`. One row is read every `speed` frames. Attack volume
  `[13,13,10]`, dropping by 1 per frame down to `[8,10,5]`. Drum: noise on channel C
  for `drums[d].frames` frames.
- **Effects**: initial `period`, `delta` per frame, `frames`; tone or noise on channel C.
- **Voice**: `sample_4bit.bin` (5214 4-bit samples, ~8 kHz); each nibble is played as the
  AY volumes in `ay_volume_table`. `sample.wav` is the linear version.

## 8. Random numbers

16-bit xorshift (seed `0x2B7D`; on the title screen it is incremented every frame to vary
the seed). It only affects the initial positions of gaps and enemies.

## 9. Differences from the description published on itch.io

The itch.io page (roman126) describes the changes in **version 2**; the binary analysed
here is **v4**. This specification follows the v4 code. Differences:

| Description (v2) | v4 code |
|---|---|
| The spider changes direction at random | No enemy changes direction at random; they only bounce at the edges or chase (kinds 2 and 7) |
| Level 1: two slow green "blobs" | Level 1: enemies of kind 0 and 1 (different), colour variant `(level+i) mod 3` |
| Levels cycle through three tunes | 12 different in-game tunes (`level_music`), plus title, level complete and game over |
| The border flashes while falling **and while sitting** | The border flashes for 30 frames when a fall starts (not while stunned) |

In agreement: 8 enemy kinds, one new kind per level; a robot that stops and starts
(kind 5); hoppers (kinds 3 and 4, the latter hops twice as high); levels 1–2 at half
speed; a different gap size per floor that shrinks with the level; longer stun for longer
falls; a whistle while falling and a thud on landing; a stick logo that assembles,
wiggles and flies apart with cycling colours.
